## hexdoc

Source: <https://github.com/object-Object/hexdoc>

The pattern registry data in `public/data/patterns.json` is generated by HexTools from hexdoc's
exported Hex Casting pattern manifests (`packages` in the JSON lists the exact versions). hexdoc is
MIT licensed; the generated data is redistributed here as data, with attribution.

---

## HexBug

Source: <https://github.com/FallingColors/HexBug>

hexParse is HexBug's pattern notation. HexSimulator implements the same token syntax
(`num_<n>`, `mask_<mask>`, direction-prefixed signatures, named patterns, special tokens). No HexBug
code is copied; the syntax and semantics are reimplemented from the documented behaviour and
HexTools' parser.

---

## Hex Casting (HexMod)

Source: <https://github.com/FallingColors/HexMod>

Pattern geometry, number literal encoding, iota taxonomy and rendering conventions follow Hex
Casting by petrak (MIT). No Java code is included; the behaviour is reimplemented in TypeScript.

---

## MieLib HexCLI

Source: the MieLib project (HexCLI).

The HTTP protocol in `docs/PROTOCOL*.md` and the iota JSON shape are modelled on MieLib's HexCLI
remote interface. MieLib itself is not bundled or required.
